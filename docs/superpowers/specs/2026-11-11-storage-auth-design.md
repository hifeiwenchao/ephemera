# Redis 消息存储与账号认证

用户已确认消息/历史放 Redis，用户资料与会话设置保留 MySQL；使用本地 root MySQL3306及 Redis6379。旧库只作保留备份，现有消息和用户不重置。消息按绝对时间原生 TTL 删除，关闭到期的消息不设置 TTL。会话索引只含消息ID，后台清理过期索引并通知客户端。

用户新增注册/登录：注册需唯一用户名、密码、邮箱及邮箱验证码；支持用户名密码和邮箱验证码登录。用户名3–32个ASCII字母/数字/下划线，忽略大小写唯一；邮箱小写归一化且唯一；密码8–128字符，scrypt哈希；昵称可选≤80字符。注册必须通过验证码验证邮箱。旧演示用户数据保留，但不提供默认密码或免认证访问。

验证码为6位随机数字，5分钟有效、一次使用、最多5次错误，发送间隔60秒，同时限制邮箱和IP频率。邮件通过本地 Mailpit 收件箱测试，之后可配置SMTP。验证码与会话仅存Redis；验证码不写日志或HTTP响应。登录随机会话令牌只放HttpOnly/SameSite cookie，服务端存令牌摘要，7天到期，退出撤销；HTTP和WebSocket均校验身份及会话成员，停用X-User-Id演示身份。

前端替换演示用户引导，提供注册、密码登录、邮箱验证码登录、退出，以及本地测试邮箱入口，保留原聊天布局与到期体验。产品暂不改名，中文名限定两个字，筛查后交用户选择。

验证包括Redis独立命名空间测试、验证码过期/重放/限流、账号唯一性与会话隔离、邮件实际接收、浏览器注册/登录、Nginx代理下双WebSocket收发和原生TTL删除。私有配置与数据备份不得进入Git或交付压缩包。
